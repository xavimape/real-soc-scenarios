## Resumen Ejecutivo

En esta investigación, un analista de SOC detecta y contiene exitosamente un ataque de phishing dirigido en menos de 70 minutos. El caso demuestra cómo las herramientas modernas de detección de correo electrónico pueden identificar rápidamente amenazas cuando están correctamente configuradas, y la importancia de la respuesta ágil ante alertas de seguridad.

**Métricas clave:**
- Tiempo de detección: 7 minutos
- Tiempo de contención: 28 minutos
- Datos comprometidos: Ninguno (contenido exitosamente)
- Técnica MITRE principal: T1566.002 (Phishing - Spearphishing Link)

## 1. Alerta inicial

El ticket fue creado automáticamente cuando Microsoft Defender for Office 365 detectó una anomalía en un correo electrónico entrante.

### Detalles de la Alerta

```
Alert Name:        Phishing email detected
Severity:          High
Detection Source:  Microsoft Defender for Office 365
Alert ID:          a1b2c3d4-e5f6-7890-abcd-ef1234567890
Status:            New
Assignment Group:  SOC L1
Assigned to:       Prasanna
SLA Response Time: 1 hour
```

### ¿Por qué fue marcado como Alto?

Microsoft Defender identificó **varios indicadores sospechosos**:

1. **URL Maliciosa**: El correo contiene un enlace a `secure-update[.]com/verify`
2. **Dominio Nuevo**: `secure-update[.]com` fue registrado hace solo 2 días
3. **SPF/DKIM/DMARC**: Falla en todas las validaciones de autenticación de correo
4. **JavaScript Ofuscado**: El archivo adjunto contiene código JavaScript obfuscado

### ¿Qué Significan Estos Fallos?

| Verificación | Resultado | Significado |
|---|---|---|
| **SPF** | <Fail />Fail | El dominio `secure-update[.]com` no autoriza al servidor que envía para entregar correos |
| **DKIM** | <Fail />Fail | El correo no tiene firma digital válida del remitente |
| **DMARC** | <Fail />Fail | Falla la política de autenticación del dominio |

**Conclusión**: Todos estos fallos juntos = **muy probable que sea phishing**

## 4. Análisis del archivo adjunto

El correo adjunto es: `Invoice_042024.html`.

<Warn />**Muestra sintética.** Este es un caso educativo: el adjunto no proviene de
un incidente real, es una reconstrucción escrita para el ejercicio. El archivo
completo se transcribe abajo, y el hash corresponde a ese contenido exacto — se
puede reproducir con `sha256sum` sobre el archivo guardado tal cual.

```html
<!doctype html>
<html>
<head><meta charset="utf-8"><title>Invoice 042024</title></head>
<body>
<script>
var _0x4f2c=['hxxps://secure-update[.]com/verify','billing_info'];
(function(_0x2d8a45,_0x4a3b20){
  var _0x1f4a96=function(_0x4f2c23){
    while(--_0x4f2c23){
      _0x2d8a45['push'](_0x2d8a45['shift']());
    }
  };
  _0x1f4a96(++_0x4a3b20);
}(_0x4f2c,0x1a7));
</script>
</body>
</html>
```

```
Filename:      Invoice_042024.html
File Type:     HTML + JavaScript
Size:          393 bytes
Hash (SHA256): 9d7012c9b6d9436ea90b4b74554ec6f07a2d69d49caf8bab702290c63dbffcb5
Verdict:       Malicious (muestra de laboratorio)
```

### Qué hace el código

El array de cadenas está rotado y se reordena en tiempo de ejecución, así que
leyendo el archivo no se ve la URL de destino: aparece recién cuando el script
corre. Es ofuscación de manual, suficiente para pasar una inspección visual
apurada y para complicar una regla que busque la URL como texto plano.

**Propósito**: redirigir al usuario a la página de phishing cuando abre el archivo
HTML en el navegador.

## 6. Acciones de contención

Una vez confirmado como phishing, el analista ejecuta acciones inmediatas:

### Acción 1: Bloquear Dominio (09:25)

```
Tool: Microsoft 365 Defender
Action: Add secure-update[.]com to organization-wide blocked sender list
Effect: Todos los correos de este dominio son rechazados
Status: Completed
```

### Acción 2: Eliminar Correo (09:28)

```
Tool: Exchange Admin Center
Action: Purge malicious email from all user mailboxes
Message: "Urgent: Update Your Account Information"
From: billing@secure-update[.]com
Effect: Email eliminado de todos los buzones de entrada
Users Protected: Entire organization
Status: Completed
```

### Acción 3: Notificar al Usuario (09:30)

El usuario es notificado sobre el intento de phishing y se le advierte:
- No hacer clic en enlaces de correos de remitentes desconocidos
- Usar el portal legítimo (no enlaces de correo)
- Reportar correos sospechosos

### Lecciones Aprendidas

1. **Defensa en profundidad funciona**: Defender detectó y alertó aunque el correo llegó a la bandeja de entrada
2. **Respuesta rápida es crítica**: El analista investigó en 7 minutos; contención completa en 28 minutos
3. **Conciencia del usuario importa**: El usuario no hizo clic (en este caso), pero se debería entrenar más
4. **SPF/DKIM/DMARC es efectivo**: Los fallos en autenticación fueron pistas clave

### Recomendaciones

- <Pass />Implementar filtrado de correo con machine learning
- <Pass />Capacitación regular de conciencia de phishing
- <Pass />Autenticación multifactor (MFA) obligatoria
- <Pass />Monitorear URL/dominios nuevos sospechosos
