## Executive summary

A SOC analyst detects and contains a targeted phishing attack in under 70 minutes. The case shows how modern email detection tools identify threats quickly when they are configured properly, and why a fast response to a security alert matters as much as the detection itself.

**Key metrics:**
- Time to detection: 7 minutes
- Time to containment: 28 minutes
- Data compromised: none — contained successfully
- Primary MITRE technique: T1566.002 (Phishing - Spearphishing Link)

## 1. The initial alert

The ticket was created automatically when Microsoft Defender for Office 365 spotted an anomaly in an inbound email.

### Alert details

```
Alert Name:        Phishing email detected
Severity:          High
Detection Source:  Microsoft Defender for Office 365
Alert ID:          a1b2c3d4-e5f6-7890-abcd-ef1234567890
Status:            New
Assignment Group:  SOC L1
Assigned to:       Prasanna
SLA Response Time: 1 hour
```

### Why was it rated High?

Microsoft Defender picked up **several suspicious indicators at once**:

1. **Malicious URL**: the email links to `secure-update[.]com/verify`
2. **Newly registered domain**: `secure-update[.]com` was registered two days earlier
3. **SPF/DKIM/DMARC**: every email authentication check fails
4. **Obfuscated JavaScript**: the attachment carries obfuscated code

No single one of these would be conclusive. Together they are hard to explain away.

### What do these failures mean?

| Check | Result | Meaning |
|---|---|---|
| **SPF** | Fail | `secure-update[.]com` does not authorise the sending server to deliver mail on its behalf |
| **DKIM** | Fail | The message carries no valid digital signature from the sender |
| **DMARC** | Fail | The domain's own authentication policy rejects the message |

**Conclusion**: three failures together make phishing the overwhelmingly likely explanation.

The email contains a link: `hxxps://secure-update[.]com/verify` (indicators are published defanged).

Confidence:       HIGH
URL Category:     Phishing

```

### The landing page

The analyst opens the URL from an isolated machine on the internal network:

1. The **phishing page imitates** the legitimate account update portal
2. It **asks for the user's email and password**
3. It **redirects to a confirmation page** so nothing feels wrong afterwards
4. The **submitted data goes to attacker-controlled servers**

```

### What the code does

The string array is rotated and reordered at runtime, so reading the file never shows
you the destination URL — it only appears once the script executes. This is textbook
obfuscation: enough to survive a hurried visual inspection and to break a detection
rule that looks for the URL as plain text.

**Purpose**: send the user to the phishing page when they open the HTML file in a browser.

## 6. Containment

Once phishing is confirmed, the analyst acts.

### Action 1: block the domain (09:25)

```
Tool: Microsoft 365 Defender
Action: Add secure-update[.]com to organization-wide blocked sender list
Effect: All mail from this domain is rejected
Status: Completed
```

### Action 2: purge the email (09:28)

```
Tool: Exchange Admin Center
Action: Purge malicious email from all user mailboxes
Message: "Urgent: Update Your Account Information"
From: billing@secure-update[.]com
Effect: Email removed from every inbox
Users Protected: Entire organization
Status: Completed
```

### Action 3: notify the user (09:30)

The user is told about the phishing attempt and reminded to:
- Not click links in email from unknown senders
- Reach the portal directly rather than through an email link
- Report anything that looks off

### Lessons learned

1. **Defence in depth works**: Defender detected and alerted even though the email reached the inbox
2. **Speed is the deciding factor**: 7 minutes to start investigating, 28 minutes to full containment
3. **User awareness matters**: this user did not click, but that was partly luck and deserves training
4. **SPF/DKIM/DMARC earn their keep**: the authentication failures were the clearest early signal

### Recommendations

- Add machine-learning-based mail filtering
- Run phishing awareness training on a regular cadence
- Make multi-factor authentication mandatory
- Monitor newly registered domains and suspicious URLs
